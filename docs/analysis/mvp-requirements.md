# Требования к MVP

Требования консолидированы из приложенного MVP-документа. Это планируемые критерии, а не подтверждение реализованных функций.

## Функции

| ID | Функция | Ожидаемое поведение |
|---|---|---|
| F1 | Загрузка | Выбор или drag-and-drop `.log`/`.txt`, проверка формата и размера до 100 МБ, понятная ошибка и индикация загрузки |
| F2 | Потоковый парсинг | Построчно извлекать уровень, время, ресурс и операцию без чтения всего файла в память; повторяющиеся подряд строки группировать |
| F3 | Индикация | Подсвечивать Error красным, Warning жёлтым, Info нейтрально, успешные изменения зелёным; показывать счётчики |
| F4 | JSON | Искать JSON-фрагменты в строках, валидировать и показывать деревом; повреждённый JSON не останавливает разбор |
| F5 | Фильтрация и навигация | Фильтр по уровню; синхронный переход между диаграммой, проблемой и строкой лога; неизвестную длительность обозначать явно |
| F6 | Маскирование (опционально) | Маскировать IP-адреса и токены, если функция будет включена в MVP |

## Критерии приёмки из исходного MVP

- Файл до 100 МБ обрабатывается без падения; память контролируется нагрузочным тестированием.
- Ошибки и предупреждения подсвечиваются, счётчики сверяются с эталонными логами.
- JSON разбирается во всех строках, где он присутствует; повреждённый JSON не ломает обработку.
- Диаграмма согласуется с порядком и длительностью операций на контрольных примерах.
- Временные файлы удаляются, история анализов не сохраняется.
- Неподдерживаемый формат и размер свыше лимита отклоняются понятным сообщением.
- Сквозной сценарий работает на публичном URL после появления деплоя.
- Сокращение времени диагностики подтверждается сравнением на нескольких тестировщиках.

## Допущения

Лимит 100 МБ, потоковая передача и отсутствие сохранения файлов — требования/гипотезы из документов. Их нужно подтвердить с куратором или заказчиком. Не считать реализованными до появления кода и проверки.
